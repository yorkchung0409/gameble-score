# 架构风险与优化清单

## 已登记：麻将规则单一核心

云函数和云托管共享同一数据库。金额、抽水、冲正汇总和房间可见性已抽到 `shared/mahjong-rules.js`，并由两端共同调用；两个传输层只负责 OpenID 鉴权、数据库连接和请求适配。

覆盖范围：成员关系、座位、金额校验、茶水费、转账、冲正、统计汇总与房间版本。

目标：云函数故障回退云托管时，仍执行同一套业务规则与同一组回归用例。

## 当前审查范围

- 房间读取与成员权限
- 云函数与云托管规则漂移
- 汇总缓存失效与并发
- 实时同步和缩容回退
- 归档任务的多实例行为
- 发布包、数据库迁移和生产版本一致性

## 2026-09-08 审查结果

### 本轮修复

- 房间详情读取：进行中房间要求当前 OpenID 是活跃成员；归档房间允许曾加入的成员查看历史。云托管私有调用也使用相同约束。旧 Web 房间码访问不携带 OpenID，保留原兼容行为。
- 发布顺序：小程序识别旧云函数的“不支持操作”响应，并对昵称保存安全回退云托管，避免灰度发布期间不可改昵称。

### 后续结构性优化

- 单一麻将规则核心：本轮已统一金额、单人抽水、冲正汇总、余额、房间可见性，并用跨运行时契约测试锁定结果。函数仍使用原生 SQL、云托管使用 Drizzle；新业务规则必须先加入共享核心和契约测试，不再复制计算代码。
- 云托管详情回退：函数主路径已有按房间版本的统计缓存，云托管回退路径仍是全量汇总，应在单一核心改造时统一。
- 运行时同步：跨实例版本同步仅查询本实例活跃房间，间隔为 5 秒；当前量级可接受，活跃房间增长后评估事件推送或更长间隔。
- 依赖更新：官方 registry 审计当前为 4 个 moderate，涉及 NestJS 与 React Router 的 major 升级；应单独做兼容性发布，不与账本规则改造混合。
